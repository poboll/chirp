Features

为「只报信」而生

关注一件事：把当前应用告诉博客。保留清楚的状态，也保留暂停的选择。

轻

纯 AppKit + Swift Package，零第三方依赖；LSUIElement 无 Dock 图标，只住菜单栏。

省

应用切换后防抖 3 秒；Companion 每 30 秒续期，旧云函数默认每 240 秒续期。

稳

正常时保持系统单色；失败后 5–60 秒退避重试，暂停取消重试。橙色表示等待或暂停，红色表示失败。睡眠唤醒补报，配置错误保留原文件。

有图标

优先使用图标 CDN。旧模式可回落本机图标；Companion 仅发送 HTTPS 图标（见 说明）。

How it works

一只小鸟，两代接口

按配置中的 endpoint 选择协议。升级后端会带来新接口，设备配对与主题开关仍需配置。

应用切换 ──防抖 3s──▶ chirp ├─ Companion PUT /presence → 租约 + 广播 → Live Desk └─ 旧云函数 POST ps/update → 缓存 + 广播 → 旧活动组件
Install

一分钟装好

macOS 13+（Apple Silicon）。安装后按博客版本配置：新版使用 Companion 设备配对，旧版使用 ps/update 云函数。

一键安装

curl · release · launchagent

$ curl -fsSL https://raw.githubusercontent.com/poboll/chirp/main/scripts/install.sh | bash

旧版配置（可选）

密钥只落本机 · 600 权限 · 不经 GitHub

$ bash install.sh \ --endpoint https://your-blog.example.com/api/v3/fn/ps/update \ --key 与 snippet 一致的密钥

不传参数也行：装好后点菜单栏小鸟 → 打开配置文件（⌘,）手动填。

或从源码构建

swift package · 两行

$ sh scripts/build-app.sh # 构建 + 安装 $ sh scripts/install-launch-agent.sh # 开机自启
Icon pipeline

图标从哪来

应用图标由主题映射和 CDN 提供。旧模式还支持本机 data URI，Companion 未命中 CDN 时仅上报应用名。

TIER 1

主题内置映射

自建主题可复用 Innei/reporter-assets 的名称映射（Xcode、VS Code 等常见开发软件，含中文应用名）—— 该仓库未声明 License，二次分发前请先确认。

TIER 2

app-icons CDN

poboll/app-icons 的 manifest（约 240 个常见 macOS 应用）映射成 jsdelivr 图标直链上报，manifest 每日自动刷新。

TIER 3

data URI 兜底

仅旧云函数支持本机图标内嵌上报。Companion 不接受 data URI；图标库未命中时，主题可使用自己的映射。

Integration · v1.2.0

新版博客，直接接 Companion

mx-core 内置接口 + Yohaku / Live Desk。旧版 chirp 1.1.0 不能直接使用新协议，请先更新。

确认后端能力

公开读取，无需密钥

curl -fsS https://your-api.example.com/api/v3/companion/capabilities

返回的 presenceSchemaVersions 应包含 2。后端升级不会自动把旧 key 转换为设备令牌。

配对这台 Mac

只授权前台应用状态

在后台 Companion 设备管理生成配对码，仅勾选 companion:presence:write。在源码目录执行助手并交互输入配对码：

python3 scripts/pair-companion.py --api-base https://your-api.example.com/api/v3

需要 Python 3。助手会备份旧配置，将设备令牌写入本机配置（0600），不会输出令牌。

刷新并看博客

客户端 + 主题分别确认

点小鸟 → ⌘R 重读配置。菜单显示已上报、服务端应用读回一致后，在主题启用 module.liveDesk.enable，打开博客确认。只收到上报确认还不能证明网页已显示。

使用 Shiro / 自建旧活动组件？展开旧云函数接入

下面是旧版云函数运行环境的示例；不是 Companion 的配置。路径 ps/update，Method POST，将 YOUR_SECRET_KEY 换为强随机密钥。新版 core 若返回 500，需要按当前函数运行环境调整，或随新主题迁移至 Companion。

const AUTH_KEY = 'YOUR_SECRET_KEY' function assetAuth(ctx: Context) { const body = ctx.req.body || {} if (ctx.isAuthenticated) return if (body.key !== AUTH_KEY) { ctx.throws(401, 'Unauthorized') } } export default async function handler(ctx: Context) { const method = ctx.req.method.toLowerCase() switch (method) { case 'get': { return GET(ctx) } case 'post': { const body = ctx.req.body || {} if (!body.process && !body.media) { return GET(ctx) } assetAuth(ctx) return POST(ctx) } default: { ctx.throws(405, 'Method Not Allowed') } } } interface Media { title: string artist: string } interface Process { name: string iconBase64?: string iconUrl?: string description?: string } async function GET(ctx: Context) { const [processInfo, mediaInfo] = await Promise.all([ ctx.storage.cache.get<Process>('ps'), ctx.storage.cache.get<Media>('media'), ]) // The frontend api-client unwraps the standard { code, data } envelope, // so the read branch must return one. return { code: 200, message: '', data: { processName: processInfo?.name, processInfo, mediaInfo, }, } } async function POST(ctx: Context) { const [cachedProcessInfo, cachedMediaInfo] = await Promise.all([ ctx.storage.cache.get<Process>('ps'), ctx.storage.cache.get<Media>('media'), ]) const ts = +new Date() const body = ctx.req.body || {} const psInfo = body.process as Process | undefined const mediaInfo = body.media as Media | undefined if (psInfo && psInfo.name !== cachedProcessInfo?.name) ctx?.broadcast?.('ps-update', { processInfo: psInfo, process: psInfo.name, ts, }) if (mediaInfo && cachedMediaInfo?.title !== mediaInfo.title) ctx?.broadcast?.('media-update', mediaInfo || null) if (mediaInfo) { await ctx.storage.cache.set('media', mediaInfo, 10) } if (psInfo) { await ctx.storage.cache.set('ps', psInfo, 300) } return { ok: 1, mediaInfo: cachedMediaInfo, process: cachedProcessInfo?.name, processInfo: cachedProcessInfo, timestamp: +new Date(), } }

旧客户端配置 endpoint 为完整函数地址，key 与函数密钥相同；旧活动组件也须读取此函数。读取使用空对象 POST。

API contract

接口各自负责什么

Companion 的设备令牌与旧云函数密钥相互独立。不会向未知接口试发凭据。

协议调用鉴权 / 行为
Companion v2PUT /companion/presenceBearer 设备令牌；更新前台应用，90 秒租约
Companion v2POST /companion/presence/clearBearer 设备令牌；暂停、睡眠、正常退出时清除
Companion v2GET /companion/presence/public公开；读取 projection，null 表示暂无有效在线状态
旧云函数POST /fn/ps/update写入带 key 和 process；空对象读取公开缓存

生产地址通常带 /api/v3 前缀。Companion 请求使用 schema yohaku.companion.presence v2，协议兼容头 x-yohaku-companion-version: 1.7.3，不代表 chirp 自身版本。

心跳

30 秒续期

Companion 90 秒租约，心跳最多 30 秒一次。断网或强制退出后，租约到期自动离线。

暂停

立即清除

Companion 主动清除；旧模式停止上报后等待函数缓存到期。

确认

读回服务端

验证 HTTP 状态与成功确认。菜单明确写「服务端应用」，网页还需确认主题开关与渲染。

Privacy

只报应用，随时暂停

上报应用名、可选图标与时间。窗口标题、输入内容、屏幕截图与媒体都不采集。

凭据

设备独立授权

Companion 仅需 presence 写权限。站长 API key 不进入 chirp 配置，设备可在后台单独撤销。

本机

配置权限 0600

~/.config/chirp/config.json 保存令牌。配对前备份旧配置；截图、源码与 Release 中不包含凭据。

传输

HTTPS + 禁止重定向

只向配置端点提交，不沿重定向转发令牌。失败只展示错误代码，不回显服务端可能包含凭据的消息。

Ecosystem

与博客的这一代对齐

chirp 是独立上报器，遵循 mx-space 的接口契约。

后端

mx-space/core

新版内置 Companion 能力、设备配对和在线状态接口。无需为 Companion 新建 ps/update 函数。

前端

Yohaku / Live Desk

Live Desk 读取 Companion 公开投影。是否显示由主题配置与状态共同决定。

旧版

ProcessReporterMac

旧上报器及云函数是 chirp 的灵感来源。Shiro 或自建旧活动组件仍可选择云函数模式。

Config

按协议填一份配置

文件位于 ~/.config/chirp/config.json。可选字段可以省略；保存后点 ⌘R 重读配置。

Companion

设备配对后自动写入

{
  "endpoint": "https://your-api.example.com/api/v3/companion/presence",
  "deviceId": "配对返回的 UUID",
  "deviceToken": "配对返回的设备令牌"
}

旧云函数

继续使用原共享密钥

{
  "endpoint": "https://your-api.example.com/api/v3/fn/ps/update",
  "key": "与函数 AUTH_KEY 一致的密钥"
}

chmod 600 ~/.config/chirp/config.json。可选 debounceSeconds 默认 3，heartbeatSeconds 旧版默认 240、新版默认 30；新版较大值自动压至 30。

白色 / 系统单色

上报确认

最近一次上报得到服务端确认。展开菜单比较当前应用与服务端应用。

橙色

等待或暂停

等待首次上报，或你已暂停。⌘P 继续上报；⌘Q 正常退出。

红色

展开查看原因

401 检查配对凭据；404 检查路径；426 检查协议；500 检查服务端日志。

旧版黑色小鸟来自 macOS 模板色，在浅色菜单栏属正常外观，不能据此判断上报成功。v1.2.0 正常时仍为系统单色，深色菜单栏为白色；暂停与失败保留状态提示。更多说明见 README。
