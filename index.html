Features

为「只报信」而生

上游 ProcessReporter 的功能砍到只剩一件事——报信。没有 Slack、没有 Discord、没有 S3，换来极小与极稳。

轻

纯 AppKit + Swift Package，零第三方依赖；LSUIElement 无 Dock 图标，只住菜单栏。

省

只在应用切换时上报（3 秒防抖），每 4 分钟心跳续期；服务端缓存 5 分钟。

稳

LaunchAgent KeepAlive 常驻；睡眠唤醒自动补报；失败小鸟变红；配置损坏绝不覆盖。

有图标

三层自动回落，新装软件零操作（见 图标从哪来）。

How it works

一只小鸟的工作

防抖、心跳、回落，全部自动。你唯一要做的是装上它、填两行配置。

切换应用 ──防抖 3s──▶ POST /api/v3/fn/ps/update { key, process: { name, iconUrl? } } │ ▼ mx-space snippet 缓存 5 分钟 + WebSocket 广播 │ ▼ 博客导航栏「正在使用 XX」 （自建主题 / Shiro 时代方案）
Install

一分钟装好

macOS 13+（Apple Silicon）。先在 mx-space 后台自建 ps/update 函数 —— 它不随主题自带，是最小的一步自建代码。

一键安装

curl · release · launchagent

$ curl -fsSL https://raw.githubusercontent.com/poboll/chirp/main/scripts/install.sh | bash

注入配置（可选）

密钥只落本机 · 600 权限 · 不经 GitHub

$ bash install.sh \ --endpoint https://your-blog.example.com/api/v3/fn/ps/update \ --key 与 snippet 一致的密钥

不传参数也行：装好后点菜单栏小鸟 → 打开配置文件（⌘,）手动填。

或从源码构建

swift package · 两行

$ sh scripts/build-app.sh # 构建 + 安装 $ sh scripts/install-launch-agent.sh # 开机自启
Icon pipeline

图标从哪来

「正在使用」的应用图标按三层回落，绝大多数应用不需要任何手动配置——新装软件即刻有图标。

TIER 1

主题内置映射

自建主题可复用 Innei/reporter-assets 的名称映射（Xcode、VS Code 等常见开发软件，含中文应用名）—— 该仓库未声明 License，二次分发前请先确认。

TIER 2

app-icons CDN

poboll/app-icons 的 manifest（约 240 个常见 macOS 应用）映射成 jsdelivr 图标直链上报，manifest 每日自动刷新。

TIER 3

data URI 兜底

两层都未命中时直接抓本机应用图标内嵌上报——新装任何软件立即可用，进了图标库后自动切轻量 CDN 模式。

Integration

接入 mx-space

三步：服务端建一个函数 → 主题开「正在使用」→ 小鸟填两行配置。全程约五分钟。

服务端：建 ps/update 函数

mx-space 管理后台 → Serverless 函数 → 新建

路径填 ps/update，Method 选 POST，粘贴下面这段（把 YOUR_SECRET_KEY 换成你自己的强随机密钥）：

const AUTH_KEY = 'YOUR_SECRET_KEY' function assetAuth(ctx: Context) { const body = ctx.req.body || {} if (ctx.isAuthenticated) return if (body.key !== AUTH_KEY) { ctx.throws(401, 'Unauthorized') } } export default async function handler(ctx: Context) { const method = ctx.req.method.toLowerCase() switch (method) { case 'get': { return GET(ctx) } case 'post': { const body = ctx.req.body || {} if (!body.process && !body.media) { return GET(ctx) } assetAuth(ctx) return POST(ctx) } default: { ctx.throws(405, 'Method Not Allowed') } } } interface Media { title: string artist: string } interface Process { name: string iconBase64?: string iconUrl?: string description?: string } async function GET(ctx: Context) { const [processInfo, mediaInfo] = await Promise.all([ ctx.storage.cache.get<Process>('ps'), ctx.storage.cache.get<Media>('media'), ]) // The frontend api-client unwraps the standard { code, data } envelope, // so the read branch must return one. return { code: 200, message: '', data: { processName: processInfo?.name, processInfo, mediaInfo, }, } } async function POST(ctx: Context) { const [cachedProcessInfo, cachedMediaInfo] = await Promise.all([ ctx.storage.cache.get<Process>('ps'), ctx.storage.cache.get<Media>('media'), ]) const ts = +new Date() const body = ctx.req.body || {} const psInfo = body.process as Process | undefined const mediaInfo = body.media as Media | undefined if (psInfo && psInfo.name !== cachedProcessInfo?.name) ctx?.broadcast?.('ps-update', { processInfo: psInfo, process: psInfo.name, ts, }) if (mediaInfo && cachedMediaInfo?.title !== mediaInfo.title) ctx?.broadcast?.('media-update', mediaInfo || null) if (mediaInfo) { await ctx.storage.cache.set('media', mediaInfo, 10) } if (psInfo) { await ctx.storage.cache.set('ps', psInfo, 300) } return { ok: 1, mediaInfo: cachedMediaInfo, process: cachedProcessInfo?.name, processInfo: cachedProcessInfo, timestamp: +new Date(), } }

主题：接上读接口

自建主题 / Shiro 时代方案

在你自己的主题里把活动模块指向这个函数。注意：新一代 Yohaku 的 Live Desk 走的是 mx-core 内置 Companion 接口（GET /companion/presence/public），不是这套 ps/update 函数；下面仅是自建/Shiro 时代配置的形态示意：

{ "module": { "activity": { "endpoint": "https://kami.caiths.com/api/v3/fn/ps/update" } } }

保存后导航栏就会出现「正在使用 XX」实时徽标，右侧小字是在读人数。

本机：装小鸟、填两行

endpoint + key，密钥只落本机

$ bash install.sh \ --endpoint https://你的域名/api/v3/fn/ps/update \ --key 和 snippet 里一致的密钥
API contract

接口是怎么样的

一个函数，两个分支：带 process 的 POST 是上报（要密钥），空 body 的 POST 是读取（公开，给主题用）。

调用鉴权行为
POST body 含 process / media必须 key 匹配，否则 401写入缓存；应用名变化时经 WebSocket 广播 ps-update
POST 空 body公开返回当前缓存（{code:200, data:{processName, processInfo, mediaInfo}}）

上报 payload（chirp 自动组装，无需手写）：

{ "key": "与 snippet 一致的密钥", "timestamp": 1730000000000, "process": { "name": "Arc", "iconUrl": "https://cdn.example.com/Arc.png", // 三层回落后选一 "iconBase64": "data:image/png;base64,...", // 兜底内嵌 "description": "可选备注" }, "media": { "title": "可选", "artist": "正在播放" } }
缓存

ps 300 秒

服务端缓存当前应用 5 分钟（media 10 秒），心跳 4 分钟一轮保证不过期。

广播

只在变化时

应用名没变不打扰 WebSocket；变了才推 ps-update 事件给所有在线访客。

读取

空 POST 即读

注意：函数以 POST 注册，直接 GET 会 404 FUNCTION_NOT_FOUND——读取也用空 body POST。

Security

权限是如何设计的

一个共享密钥，两处存放，三不原则。

共享密钥

chirp 配置里的 key 必须与 snippet 内 AUTH_KEY 一致；不匹配一律 401。这是唯一凭证。

两处存放

本机 ~/.config/chirp/config.json（权限 600）与 snippet 源码。绝不进 Release、仓库或截图。

泄露怎么办

后台改 snippet 里的 AUTH_KEY → 本机同步改配置 → ⌘R 立即刷新。旧 key 即刻失效。

读取公开

「正在使用」是给访客看的，读分支无需鉴权；上报分支必须持密钥，防伪造刷屏。

chirp （本机） ──▶ mx-core ps/update 函数 ──▶ 缓存 + WebSocket ──▶ 你的博客导航栏

⚠️ 两套机制，别配错

生态里同时存在两代方案

这是最容易踩的坑 —— 两者的接口完全不同：

① 函数订阅式（chirp 采用）：客户端 POST 到 mx-space 的 serverless 函数 /api/v3/fn/ps/update，函数写缓存并经 WebSocket 广播。适合自建、Shiro 时代、以及任何你自己写的读接口。

② mx-core Companion（新一代）：mx-core 内置 companion 模块，路由为 PUT /companion/presence、POST /companion/presence/clear、GET /companion/presence/public。Yohaku 的「Live Desk」消费的是这一条。

chirp 目前对接的是 ①。如果你要用 Yohaku 的 Live Desk（②），chirp 不能直接顶替 —— 需要另配一个中转函数，或等 chirp 适配 Companion 协议。

关于 Yohaku：完整 Web 实现为赞助后开放访问的项目，通过 GitHub Sponsors 支持作者后获取；本页只引用其公开的设计系统与 iOS 源码。

Config

配置文件怎么写

只有 ~/.config/chirp/config.json 一个文件，权限 600。下面这份直接可用——把 endpoint 和 key 换成你自己的两行，其余保持默认即可。

1 · 推荐配置（开箱即用）

图标 CDN 已是可用默认值

{ "endpoint": "https://your-blog.example.com/api/v3/fn/ps/update", "key": "与 snippet 里 AUTH_KEY 一致的密钥", "debounceSeconds": 3, "heartbeatSeconds": 240, "iconManifestUrl": "https://fastly.jsdelivr.net/gh/poboll/app-icons@main/manifest.json", "iconBase": "https://fastly.jsdelivr.net/gh/poboll/app-icons@main/icons" }

后四行可以整段删掉——chirp 内置了完全相同的默认值（见下表「默认」列）。写上只是为了让你看得见、能改。

2 · 一行命令写入

免手写，自动 600 权限

$ mkdir -p ~/.config/chirp && cat > ~/.config/chirp/config.json <<'EOF' { "endpoint": "https://your-blog.example.com/api/v3/fn/ps/update", "key": "YOUR_KEY" } EOF $ chmod 600 ~/.config/chirp/config.json

只写这两行也能跑：其余字段自动取默认值。写完点菜单栏小鸟 → ⌘R 立即刷新验证。

3 · 验证是否生效

三个地方看结果

依次确认：

1. 菜单栏小鸟 → 看「上次上报结果」是否 ✓ 2. 空 POST 读一下服务端缓存： curl -s -X POST https://your-blog.example.com/api/v3/fn/ps/update 3. 打开博客，导航栏应出现「正在使用 XX」

若第 1 步是红色 ✗：多半是 key 不匹配（401）或 endpoint 写错（404）。函数以 POST 注册，直接 GET 会 FUNCTION_NOT_FOUND。

字段说明

字段默认说明
endpoint必填ps/update 函数的完整地址，含 /api/v3/fn/ 前缀
key必填与 snippet 内 AUTH_KEY 完全一致；不一致一律 401
debounceSeconds3切换应用后等几秒再上报，避免快速切换刷屏
heartbeatSeconds240心跳续期间隔；服务端缓存 300 秒，必须小于它
iconManifestUrlapp-icons CDN应用名 → 图标清单；默认指向 poboll/app-icons，每日刷新
iconBaseapp-icons CDN图标 URL 前缀；未命中时自动回落为内嵌 data URI
默认值

删掉也能跑

四个可选字段都有内置默认值，配置里只写 endpoint + key 是合法且推荐的极简写法。

安全

600 权限

配置文件含密钥，务必 chmod 600。chirp 只读不写，损坏时也绝不覆盖你的文件。

自建 CDN

可换自己的

把 iconManifestUrl / iconBase 指向你自己的图标库即可，格式见 app-icons 的 manifest.json。
